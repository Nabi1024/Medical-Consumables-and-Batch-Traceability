# 系统架构设计

> 医用耗材批次追溯智能助手 —— 四层技术架构说明

本系统面向医院医用耗材「批次级」全生命周期追溯场景，在保障数据不出院、
满足等保三级与电子签名留痕的前提下，用 RAG + 业务 Agent 编排替代人工审核，
降低耗材管理员与质控人员的信息检索与合规判断耗时。

## 1. 总体分层

```
┌──────────────────────────────────────────────────────────┐

│  · 管理员后台 (admin_app + Jinja2 模板, JWT/RBAC)         │
│  · 命令行入口 (cli.py: demo/eval/init/serve/config)       │
└──────────────────────────────────────────────────────────┘
                          │
┌──────────────────────────────────────────────────────────┐
│ 服务层 (Service / API)                                    │
│  · FastAPI 路由：POST /chat(SSE)、/api/auth/login 等      │
│  · 统一错误码：0/40001/40101/40301/40401/41301/42901/...  │
│  · 最近 6 轮上下文拼接，引用来源标注                      │
└──────────────────────────────────────────────────────────┘
                          │
┌──────────────────────────────────────────────────────────┐
│ 智能体编排层 (Agent Orchestration)                        │
```

## 2. 关键技术决策

- **离线优先 / 零依赖回退**：在无法联网安装第三方包的环境中，FAISS→纯 Python
  暴力余弦、sklearn→纯 Python TF-IDF、JWT/password hash→纯 Python 实现、LLM→
  Mock。保证代码「拿起来就能跑、能测」，真实依赖安装后自动切换为主路径。
- **RAG 切片**：Markdown 文档按 ~500 字滑动切片，向量化入索引；检索时 BM25 与
  向量分别召回后做 RRF 倒数排名融合，取 top-k 片段回灌给模型并标注来源文件名。
- **业务 Agent 编排（Harness 而非框架绑定）**：自主实现「规划—执行—反思」循环，
  最大 5 轮；`RuleBasedPlanner` 走确定性关键词/状态路由，`LLMPlanner` 走大模型
  Function Calling，二者共用同一套工具定义，可插拔替换。
- **写类工具 HITL 强制阻断**：`draft_*` 类工具只生成草稿、返回 `need_confirm`，
  由人工在界面确认（或 `harness.confirm()`）后才真正落库，满足合规「不可篡改」要求。

## 3. 合规与数据安全

- 数据不出院：默认离线部署，知识库与数据库均落本地 SQLite。
- 等保三级：JWT 鉴权 + RBAC 角色隔离（admin / operator），操作全量写入审计表。
- 电子签名式留痕：所有写操作与 Agent 轨迹进入 `operation_logs` /
  `agent_execution_logs`，WORM（只写一次）语义，支持 CSV 导出质控。
