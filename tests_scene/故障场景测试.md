## 一、测试目标

验证系统在进程级故障、资源冲突、数据损坏、依赖缺失下的表现：故障可感知、可诊断、可恢复（RTO 达标）、数据零丢失、优雅降级。

**测试方法**：为避免破坏在役服务，故障注入使用**隔离实例**（端口 8003、独立 DB_PATH 环境变量），与在役实例（8000/8001/8002）完全隔离。

## 四、测试发现并修复的缺陷（F-06）

**现象**：知识库 docs 目录缺失时，chat_app 启动直接崩溃（`FileNotFoundError: 在 docs 下未找到任何 .md 文档`，Application startup failed）。

**根因**：`ingest_kb_if_needed()` 未捕获知识库摄取异常，启动钩子直接抛错导致服务无法启动。

**修复**：`src/chat_app.py` 中为摄取过程增加异常捕获（FileNotFoundError 与通用异常），docs 缺失时打印告警并以 `kb_ready=false` 降级启动，管理员可在后台补传文档。修复后复测：服务正常启动，health 返回 kb_ready=false，不崩溃。
